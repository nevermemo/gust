# Compiler testing

Choose the smallest test that can disprove the change, then expand only across affected compiler boundaries. Keep the locked toolchain and dependency versions.

1. Validator: accepted fixture plus single-cause rejection test with a meaningful diagnostic, in `crates/gust-macros/src/tests`. A `compile_fail` doctest in `crates/gust/src/lib.rs` covers source that rustc itself must still reject.
2. Emitter: source -> expected Slang semantics against the reviewed goldens in `tests/fixtures/`, then actual slangc compilation for supported targets.
3. Runtime: expected values from an independent host reference against GPU readback, including partial workgroups.
4. Run focused tests before workspace checks. Never regenerate expected diagnostics or goldens automatically to make a test pass.

Read [test layers](references/test-layers.md) for regression selection. Pick the check with `cargo xtask check-feature <area>` or `cargo xtask check-changed`; `cargo xtask check-format`, `cargo xtask check-lints` (Clippy, warnings denied) and `cargo xtask check-workspace` run locked formatting, lint and workspace tests. They report cargo checks only; they do not certify a GPU run or that every intended fixture exists. Evidence tiers are defined in `docs/development/VALIDATION.md`.

CPU twin tests (M3): a twin assertion adds to the independent host-reference and GPU assertions and never replaces them; the twin is never the expected value (D26). A new CPU-versus-GPU difference follows the ledger procedure: add a `KM-nn` row to `docs/SEMANTICS.md` section 7 and its case to `crates/gust-wgpu/tests/mismatch.rs` (an id guard fails if only one is done), record the measured GPU outcome, pin the Rust and twin outcomes in the overflow mode of the test crate, and never loosen an assertion. Do not chase a match for an edge case (D39). The twin opt-out is `#[kernel(cpu = "unsupported")]` (GUST-E0709, GUST-E0710 fixtures under `tests/ui`); `cargo xtask check-cpu` and `cargo xtask check-dual --check-only` need no GPU.

Workgroup kernels (M7, m7.g1): a kernel with `Workgroup` memory or a barrier has no CPU twin (GUST-E0717 without `cpu = "unsupported"`), so its only execution evidence is the GPU test `crates/gust-wgpu/tests/workgroup.rs` against an independent host sum, run by `cargo xtask check-feature workgroup`. Each barrier rule has one `tests/ui` fixture with exactly one error, so a construct that is rejected for its own sake (a `while`, a loop label, `?`) expects that older code and not a second barrier error. Reference results are built from integer-valued `f32` so that any addition order is exact and the check is bit equality.

M7 evidence and where it lives (all Gpu entries ran on the RTX 5090; the labels are in `docs/SEMANTICS.md` section 8): `crates/gust-wgpu/tests/map.rs` (the element-wise map, GPU, twin and host reference), `tests/grid.rs` (multi-dimensional dispatch and the 2^32 cap: the cap is checked on the rounded product on both backends, and the twin's decision comes from `gust::cpu::validate` because a twin run of 2^32 invocations takes days), `tests/par_for.rs` (one scenario set instantiated for the GPU and the twin), `tests/workgroup.rs` (the block reduce has no twin, so it is measured; the ids-only kernel keeps its twin and is compared with the GPU). The gust-algo tests are in `crates/gust-algo/src/tests/` (`twin.rs`, `gpu.rs`, `common.rs`): the Unit suite does not run the crate. The Gpu suite and `verify --mode gpu` run `cargo test --locked -p gust-algo` as a step of their own and require 49 `gpu::` tests by name (`ALGO_GPU_TESTS` in `xtask/src/verify.rs`), so a new GPU test needs an entry there. A float sum is checked against the per-level bound of `bound.rs` for the variant that ran, not for bit equality. The parallel CPU map (D119) is evidence that needs no adapter: `crates/gust/tests/parallel.rs` is run by the workspace test (`cargo xtask check-workspace`, `verify --mode smoke` and `full`) and, since m8.x1, by a counted step of the Unit suite (as are `pixel_twin`, `textures_twin`, `toolchain` and the `gust-compute` doc tests), and the `tests/cpu-target` case `map_case.rs` is the Cpu tier; it is not GPU evidence.

Subgroup kernels (M8, m8.s): a subgroup body has no CPU twin, so its execution evidence is `crates/gust-wgpu/tests/subgroup.rs` on the GPU against a host model, and its source evidence is the golden `tests/fixtures/subgroup.slang` (`BLESS_GOLDEN=1` writes it, the test then fails once so the diff is read) and the 12 SPIR-V files of the `subgroup` set in `GOLDEN_SPIRV_SETS`. A kernel with a portable body and a subgroup variant keeps a contract both bodies satisfy (`partial_sums`: the sum of the output), and the portable body is also run on the twin and the `cpu` target in `tests/cpu-target/kernels/src/variant.rs`. Each rule of E0745, E0747 and E0751 has a `tests/ui/subgroup-*` fixture with exactly one error and a unit test in `crates/gust-macros/src/tests/subgroup.rs`; a test file under `src/tests` may not name the barred `syn` items (use `diagnostics::testing::parse_str`) or the word `disallowed_`.

Capabilities, variants and routing (M8): the profile is part of what a test runs under, so a claim names it. `GUST_PROFILE=dev+subgroups` is the test profile for a subgroup body and `native+subgroups` the strict one; a test that must run under it goes through `cargo xtask test --suite Gpu --profile dev+subgroups [--test <target>]` (the suite counts each target against `GPU_TARGET_PINS` and requires the line that shows the build received the capability), and `cargo xtask check-difftest` runs a `dev` and a `dev+subgroups` batch whose export records must be byte equal. A variant or capability rule has a `tests/ui/variant-*` or `subgroup-*` fixture with one error (E0740 to E0744, E0750) and a unit test in `crates/gust-macros/src/tests/variant.rs`; the portable floor has `tests/ui/limits-*` (E0746); the manifest table has `profile-manifest-*` (E0753). The helper-backed `cargo-gust` tests (`testdata::variant`) are named steps of the Slangc suite. A routed kernel is proved by `tests/ui/typed-call-routed-*` (the call-site consequence), `cargo xtask check-dual` E4, `cargo xtask check-cpu-target` E-j and `cargo xtask check-routing` (the driver, with `--check-only` for CI); all of those are `Cpu` evidence, and only the `gpu` case of `check-routing` runs on an adapter. A refusal that needs a capability the machine lacks is tested over fake feature sets (`crates/gust-wgpu/src/device.rs`), not skipped.

M9 evidence (D163, D166): the generative differential test in `tests/difftest` is stamped with `DIFFTEST_FORMAT` and a change to the program space bumps it. Formats 8 to 13 are the M9 spaces: 8 methods, 9 enums and `match`, 10 value `match`, integer patterns and tuples, 11 arrays, 12 closures, 13 traits and generics (`docs/development/DIFFTEST.md` has one section per format, with the program space, the pins and the attempt bases). A batch is 16 programs; a new space cuts slots from older ones, and the older pins are read with their own stamp, so a format bump must keep every earlier pin passing. A mismatch between the GPU and the CPU twin in this space is a compiler bug, not a D39 note (D163); only an out-of-bounds index is D39. The other M9 tests: the golden fixtures `tests/fixtures/{methods,methods_mut,enums,traits,generics}`; UI fixtures `tests/ui/<name>` run by `cargo xtask check-ui` (one expected error, `code: none` plus a `message:` for a macro error without a rustc code); GPU tests `crates/gust-wgpu/tests/m9_*.rs` (methods, enums, match values, tuples, arrays and stored arrays, closures, traits, generics), `driver_sentinel` (the RTX 5090 array defect, D168 and D169: it expects the defect's wrong values on that adapter and Rust's values elsewhere or on the SPIR-V route) and `spirv_route.rs` (a test that claims the route asserts `Route::Spirv` in `route_events`). The collision table has its own sorted-and-unique test and a Slangc-tier capture test per entry. A claim about a count (for example the 131 golden entries of the Slang 2026.22 comparison, spike SL22) states how it was counted (`[shader(` lines of the fixtures at a named commit).
