# Compiler testing

Choose the smallest test that can disprove the change, then expand only across affected compiler boundaries. Keep the locked toolchain and dependency versions.

1. Validator: accepted fixture plus single-cause rejection test with a meaningful diagnostic, in `crates/gust-macros/src/tests`. A `compile_fail` doctest in `crates/gust/src/lib.rs` covers source that rustc itself must still reject.
2. Emitter: source -> expected Slang semantics against the reviewed goldens in `tests/fixtures/`, then actual slangc compilation for supported targets.
3. Runtime: expected values from an independent host reference against GPU readback, including partial workgroups.
4. Run focused tests before workspace checks. Never regenerate expected diagnostics or goldens automatically to make a test pass.

Read [test layers](references/test-layers.md) for regression selection. Pick the check with `cargo xtask check-feature <area>` or `cargo xtask check-changed`; `cargo xtask check-format`, `cargo xtask check-lints` (Clippy, warnings denied) and `cargo xtask check-workspace` run locked formatting, lint and workspace tests. They report cargo checks only; they do not certify a GPU run or that every intended fixture exists. Evidence tiers are defined in `docs/development/VALIDATION.md`.

CPU twin tests (M3): a twin assertion adds to the independent host-reference and GPU assertions and never replaces them; the twin is never the expected value (D26). A new CPU-versus-GPU difference follows the ledger procedure: add a `KM-nn` row to `docs/SEMANTICS.md` section 7 and its case to `crates/gust-wgpu/tests/mismatch.rs` (an id guard fails if only one is done), record the measured GPU outcome, pin the Rust and twin outcomes in the overflow mode of the test crate, and never loosen an assertion. Do not chase a match for an edge case (D39). The twin opt-out is `#[kernel(cpu = "unsupported")]` (GUST-E0709, GUST-E0710 fixtures under `tests/ui`); `cargo xtask check-cpu` and `cargo xtask check-dual --check-only` need no GPU.

Workgroup kernels (M7, m7.g1): a kernel with `Workgroup` memory or a barrier has no CPU twin (GUST-E0717 without `cpu = "unsupported"`), so its only execution evidence is the GPU test `crates/gust-wgpu/tests/workgroup.rs` against an independent host sum, run by `cargo xtask check-feature workgroup`. Each barrier rule has one `tests/ui` fixture with exactly one error, so a construct that is rejected for its own sake (a `while`, a loop label, `?`) expects that older code and not a second barrier error. Reference results are built from integer-valued `f32` so that any addition order is exact and the check is bit equality.

M7 evidence and where it lives (all Gpu entries ran on the RTX 5090; the labels are in `docs/SEMANTICS.md` section 8): `crates/gust-wgpu/tests/map.rs` (the element-wise map, GPU, twin and host reference), `tests/grid.rs` (multi-dimensional dispatch and the 2^32 cap: the cap is checked on the rounded product on both backends, and the twin's decision comes from `gust::cpu::validate` because a twin run of 2^32 invocations takes days), `tests/par_for.rs` (one scenario set instantiated for the GPU and the twin), `tests/workgroup.rs` (the block reduce has no twin, so it is measured; the ids-only kernel keeps its twin and is compared with the GPU). The gust-algo tests are in `crates/gust-algo/src/tests/` (`twin.rs`, `gpu.rs`, `common.rs`): the Unit suite does not run the crate. The Gpu suite and `verify --mode gpu` run `cargo test --locked -p gust-algo` as a step of their own and require 49 `gpu::` tests by name (`ALGO_GPU_TESTS` in `xtask/src/verify.rs`), so a new GPU test needs an entry there. A float sum is checked against the per-level bound of `bound.rs` for the variant that ran, not for bit equality. The parallel CPU map (D119) is evidence that needs no adapter: `crates/gust/tests/parallel.rs` is run by the workspace test (`cargo xtask check-workspace`, `verify --mode smoke` and `full`) and by no Unit-suite step, and the `tests/cpu-target` case `map_case.rs` is the Cpu tier; it is not GPU evidence.
