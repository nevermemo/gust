# Rust GPU AST validation

Validate the whole GPU module before direct syn AST -> Slang emission. Read current dialect tests and validator first; never infer supported Rust from what syn can parse.

1. Locate the public GPU boundary and write down accepted syntax, types, calls and intrinsics for this change.
2. Use an allowlist with explicit rejection of unknown variants, tokens and modifiers. Recurse into every child, including types, attributes, signatures, patterns and nested expressions.
3. Separate syntactic checks from name/type/alias checks. A proc macro does not receive rustc's typed AST. Ensure rustc checks the intended preserved/generated Rust, or implement the restricted semantic check explicitly.
4. Emit a spanned diagnostic, not a panic or silently omitted shader code. Add a positive fixture and a targeted rejection fixture.

Read [validation contract](references/validation-contract.md) for traversal and semantic pitfalls. For diagnostic fixtures load `compiler-testing`; do not load lowering/runtime references for a validator-only change.

Map functions (M7, m7.a1, D60): `#[gpu]` on a free function has one validator, `validate_module`. The generator checks the signature itself (GUST-E0714, GUST-E0715, and GUST-E0204 for a 3-wide parameter or result) and validates the user's function as a helper of a one-function module with its attributes cleared, so every body rule is the helper rule and the 3-wide types stay legal as locals. `#[gpu]` or `#[gust::gpu]` on a function inside a `#[gpu]` module is GUST-E0716 (`is_gpu_attribute`); a rejected module goes back beside the error without those attributes (`without_nested_gpu` in `lib.rs`), so the inner attribute does not expand by itself and add follow-on errors. Fixtures: `tests/ui/map-*`.

Workgroup memory and barriers (M7, m7.g1; `validate/barrier.rs`, run from `validate/mod.rs` only after the generic visitor found no error, so a construct rejected for its own sake gets no second error): `workgroup_barrier()` is a statement-only call, accepted as a statement of a kernel body or of a top-level `for a..b` whose two bounds are integer literals, and anything else is GUST-E0414 (a helper, an `if`, a nested `for`); a kernel with a `Workgroup<[T; N]>` parameter or a barrier call has no `return` (GUST-E0415) and no `break` or `continue` in a `for` loop that holds a barrier (GUST-E0416). `Workgroup` parameters are legal on kernels only, with an element type of `f32`, `i32`, `u32`, `bool` or a vector of them, and all arrays of a kernel together stay within 16384 bytes (GUST-E0718, checked at expansion). Such a kernel must say `cpu = "unsupported"` (GUST-E0717); `cpu = "lockstep"` is GUST-E0709. Fixtures: `tests/ui/barrier-*`, `workgroup-over-16kib`, `kernel-cpu-lockstep`, and the rejection tests in `crates/gust-macros/src/tests/workgroup.rs`.

The shape classifier and the pin (MX, mx.c, D63, D94; `validate/classify.rs`, called from `expand/mod.rs` for every kernel before the profile is chosen): the rules are syntactic and conservative, and a construct the rules do not recognise makes the kernel `grid`-only with its span named, so a new accepted construct must be added to the `pixel` rules deliberately and never reach `pixel` by default. A kernel is `pixel`-compatible when its invocation parameter is immutable and never assigned (GUST-E0724); the own index has one spelling, `id.x`, `id.global_id().x` or exactly one immutable `let i = <that>;` bound nowhere else, and every output write is at it (E0725); each output (a `StorageMut` that is written) is used only as `out[own] = v` and `out.len()`, never read, compounded, written by component, rebound or passed on (E0728, which also covers a `StorageMut` that is never written); every output is definitely written, where `if` without `else` counts only when each conjunct is `own < out.len()` (E0726); there is no `return` (E0727); and nothing a fragment cannot carry: workgroup memory, a barrier, `LocalId` or `GroupId`, an atomic, a `StorageTexture2D` or `WriteTexture2D`, an explicit `workgroup_size`, no output at all, or an output element other than `u32`, `i32`, `f32` and their 2- and 4-wide vectors (all E0723). The pin is `#[kernel(shape = grid | pixel)]`: an unknown name is E0721, a repeated option, a value that is not a bare name and `shape = cpu` (a target, `GUST_PROFILE=cpu`) are E0722, and a pin outside the compatible set is an error at the pin with the code of the first excluding reason, whose message names the construct (and says how many more rule the shape out). E0729 is a profile's own refusal (`StageProfile::validate_body`) and is unreachable for `pixel` because the classifier runs first; E0730 is retired and its number is never reused. The map generator's kernel and `par_for!` kernels are `grid`-only by these rules (a loop variable, a guard on a uniform, an explicit workgroup size), and the classifier does not read the `own_index` stamp of m7.c. Fixtures: `tests/ui/shape-*` (17 rejecting ones: the four pin errors and 13 reasons; `shape-pixel-ok` and `shape-grid-ok` are the accepting ones) and the unit tests in `validate/classify/tests.rs`. The reasons with no `check-ui` fixture are workgroup memory, `LocalId`/`GroupId`, a write to a component of an output and a `StorageMut` that is never written; the unit tests pin those four. Not pinned by any test yet: the `OutputOther` reason (E0728 for an output rebound or passed to a helper), which only the classifier code covers.

Texture and sampler parameters (MX, mx.t3, D62, D64; `slang/texture.rs` holds the dialect's one table, `validate/mod.rs` the checks): the types are `Texture2D<T>`, `StorageTexture2D<F>`, `WriteTexture2D<F>` and `Sampler`; a type argument outside the dialect is GUST-E0731 (a 3-wide texel, `bool`, a format outside `R32Float`/`R32Uint`/`R32Sint` for a storage texture, a non-listed write format), a wrong arity or a visibly wrong coordinate type is E0732 (a texel address is two `u32`, a sample coordinate two `f32`), `sample` whose first argument is not a `Sampler` parameter is E0733, `sample` on integer texels is E0734, a method the texture's access does not have is E0735, and a texture or sampler used as a value (copied, passed to a helper, a `let` or struct-field type) is E0736. The checks are syntactic, so typing the rest is Slang's job; E0732 and E0734 have no `check-ui` fixture because rustc reports its own error beside the macro's and `check-ui` pins exactly one, so their unit tests in `crates/gust-macros/src/tests/regression.rs` are the pin. Fixtures: `tests/ui/texture-*`.

Subgroup operations (M8, m8.s, D140; `SUBGROUP_OPERATIONS` and the `approve_*` functions in `validate/barrier.rs`, the rest in `validate/mod.rs`): the 21 `subgroup_*` calls are found by name (a function of the module may not take one, GUST-E0745), they are not in the classifier's callee ledger (they are `BodyScan` hits that make a kernel `grid`-only, and `KindScan` skips them), and the barrier discipline is reused: a kernel that calls one is a "barrier kernel" for GUST-E0415 and E0416. A call is accepted only in a body whose `#[kernel(.., requires(subgroups))]` (set by `variant::lower` for a `#[variant]` body) says so (E0745 for a portable body or a helper) and only as the whole value of a `let` or assignment, or an operand there, at the top level of the body or of a top-level two-literal `for` (E0747); the invocation count must be a multiple of 64 (E0751). Fixtures: `tests/ui/subgroup-*` (7 rejecting, `subgroup-ok` under `dev+subgroups`) and `crates/gust-macros/src/tests/subgroup.rs`.
