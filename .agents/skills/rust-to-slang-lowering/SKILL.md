# Rust to Slang lowering

Emit Slang directly from the validated syn AST. Retain the module boundary. Small scoped symbol/type/binding tables and an emitter are appropriate; a custom instruction IR is future/optional and requires an explicit architecture request.

1. Read the validator, emitter and closest accepted fixture. State the source-to-target rule before editing.
2. Preserve evaluation order, scope, signedness, width, precedence and control flow. Map only validated intrinsics/calls.
3. Keep shader names, resource bindings and runtime metadata deterministic and generated from one contract.
4. Add a focused source -> Slang assertion, compile affected targets, and execute a nontrivial semantic case when behavior changes.

Operators whose Rust meaning depends on the operand type go through `__gust_*` overload helpers, emitted only when the module uses them, because the macro sees syntax and not types: unary `!` is `__gust_not` (`!` on `bool`, `~` on integers), and `^` and `^=` are `__gust_xor` and `__gust_xor_assign` (`!=` on `bool`, `^` on integers), since WGSL defines `^` only on integers; the `_assign` form takes the place `inout`, so it is evaluated once. `&`, `|`, `&=` and `|=` on `bool` pass through unchanged.

Products and the integer dot (M6, m6.m2; `module_lowering`, `Lowering` and `LoweringScope` in `crates/gust-macros/src/slang/mod.rs`, the table in `slang/mul_table.rs`): the emitter is a set of free functions, so the two per-module flags live in a thread-local set for the span of one `emit_kernel`. A module whose unrawed identifier tokens include `Mat2`, `Mat3` or `Mat4` is *gated*: every `*` is `__gust_mul(a, b)` and every `*=` is `(place = __gust_mul(place, b))`, and the overload table (one line per row of `MUL_PAIRS`, 39 rows) follows the prelude. Slang's `*` on two matrices is component-wise where Rust's is the matrix product, so a matrix product row is `mul(a, b)`; slangc picks the overload by the operand types and types an unsuffixed literal beside a typed operand. The gate is exact because E0203, E0324 and E0102 leave the prelude as the only way the name resolves; ungated modules keep the verbatim `*`, so every golden without a matrix is byte-identical. A `*=` whose place contains a call (anything but names, fields, indexing, arithmetic, `.global_id()` and `.len()`) is E0323: the place would be written twice. The same table generates every `Mul` and `MulAssign` impl of `gust::math` (`gust_mul_impls!` in `crates/gust-macros/src/mul_impls.rs`, invoked once in `crates/gust/src/math.rs`; `math.rs` writes no product by hand, a source test pins it), and `crates/gust/tests/diagnostics.rs` compiles every row on both targets, so adding a type means one new row in one file. A module that contains a `dot` token sends every `.dot` through `__gust_dot`: Slang's `dot` on an integer vector is `OpSDot`/`OpUDot`, which needs SPIR-V `Capability DotProduct` and is refused by naga's SPIR-V reader, so the integer overloads are the sum of the component products. The macro cannot tell a float `dot` from an integer one, so a float-only module takes the overloads too (its SPIR-V is byte-identical, its WGSL calls a helper). A product in a future `const` or array length must not become a `__gust_mul` call, because Slang cannot use a call as a size: the slice that adds constants lowers a product there with the plain `*`.

Negation (M6, m6.n; `slang/neg_table.rs`, `Lowering::neg`, the `Unary` arm of `emit_expression`): slangc's WGSL for a unary `-` on a matrix is `mat4x4<f32>(0) - m`, which naga refuses (SPIR-V is `OpFNegate` and passes), and `0.0 - m` would turn a `+0` lane into `+0`. A module gated by the matrix tokens (the same exact gate as `__gust_mul`) lowers every unary `-` whose operand is not a literal to `__gust_neg(a)`, and the table of overloads (10 rows: `f32`, `i32`, `Vec2/3/4`, `IVec2/4` as slangc's `-a`, `Mat2/3/4` as `a * -1.0`) follows the `__gust_mul` table. Under IEEE arithmetic `a * -1.0` is bit-identical to negation for every non-NaN value, `-0` included (a device that drops the sign of a zero, which Vulkan allows without `SignedZeroInfNanPreserve`, or flushes a subnormal in a multiply, may differ from the twin's sign flip: D39, measured by the `vectors` GPU test), and slangc emits it as a per-column product (WGSL) or `OpVectorTimesScalar` (SPIR-V), both of which pass naga and `spirv-val`. A negated literal keeps the plain `(-2.0)` / `(-3)`; ungated modules keep `(-a)`, so every golden without a matrix is byte-identical. Slangc's WGSL for a float vector `-v` is `vec(0) - v` (a `+0` lane stays `+0`, D39); `-v` is not scaled, so it means the same in every module. `gust::math` has `Neg` for `Vec2/3/4`, `IVec2/4` (lane by lane, so it follows the defining crate's overflow mode like a scalar) and the matrices, and every one has a row. A `-` in a future `const` or array length must stay a plain `-`, as the product must (Slang cannot use a call as a size).

Division (M6, m6.dv, D74's cure; `slang/div_table.rs`, `division_helper`, `DivisionUsage` and the `Binary` arms of `emit_expression` in `slang/mod.rs`): slangc 2026.20 folds integer `/` and `%` and refuses a divisor that folds to zero (`E30002`), even in code no invocation runs (a dead branch, `7 / (i * 0)`, `i - i`, the first iteration of an unrolled loop, a wrapping `/=`). The same operation behind a call compiles in every probed shape on WGSL and SPIR-V, so every `/`, `%`, `/=` and `%=` whose divisor is not a literal (a literal, negated or parenthesised or not, stays a plain operator: the validator rejects a literal zero, E0317) is `__gust_div(a, b)`, `__gust_rem(a, b)`, `__gust_div_assign(place, b)` or `__gust_rem_assign(place, b)`, the `_assign` forms with the place `inout` so it is evaluated once. Ungated: the macro sees syntax and not types, so any module with such an operator gets the overloads (`/` in `DIV_ROWS`: 3 scalars, 8 vector types with themselves and with their scalar; `%` in `REM_ROWS`: the 3 scalars, because `gust::math` has no `Rem` on a vector), each family once, after the `__gust_neg` table, whose body is the plain operator with no `[noinline]` (slangc inlines it in SPIR-V; the WGSL keeps `_gust_div_0(..)`, whose body is the plain `/`, so the WGSL results of D39/KM-01 to KM-03 hold unchanged and the cost is noise, spike m6.s1). A module with a literal divisor only keeps its text; a module with any other divisor has the table in its golden. A division in a future `const` or array length must stay a plain operator (Slang cannot use a call as a size), as the product and the negation must.

Wrapping methods (M7, m7.w; `wrapping_arity` in `validate/mod.rs`, the `MethodCall` arm after the `is_math_method` one in `emit_expression`, `is_pure_place`): `a.wrapping_add(b)`, `a.wrapping_sub(b)` and `a.wrapping_mul(b)` are the plain Slang `(a + b)`, `(a - b)` and `(a * b)`, and `a.wrapping_neg()` is `(0 - a)`. The macro sees no types, so the form must be right for `u32` and `i32` alike: slangc types the literal `0` as the operand's own type, while a unary `-` on a `u32` reaches WGSL as `- x`, which naga refuses (probed on 2026.20; `~x + 1` also works but reads worse). WGSL integer arithmetic wraps modulo 2^32 (section 6.2.3), so the plain operator is the whole lowering and the twin needs nothing: the preserved Rust calls the std method. A wrapping `*` is never `__gust_mul`, even in a module that names a matrix (test `wrapping_methods_lower_to_the_plain_operators_even_in_a_matrix_module`), and `wrapping_div` and `wrapping_rem` are deliberately not accepted (a zero divisor has no wrapped result). A wrong argument count is E0304; any other method with arguments is E0325 (listing the accepted methods, `ACCEPTED_METHODS`), without arguments E0305. A new accepted method goes into `wrapping_arity` or the validator's match, `emit_expression`, `is_pure_place` if it is arithmetic on its operands, `ACCEPTED_METHODS` and docs/DIAGNOSTICS.md together.

Comparison arguments and `__gust_keep` (fx.wgsl): WGSL reads `name < .. >` as a template list (a `<` after an identifier opens a candidate and any later `>` on the same nesting depth closes it, whatever follows the `>`, so `>=` and `>>` close one too; a `)` or `]` drops the candidates opened inside its brackets, `=`, `:`, `;` and `{` drop all of them, and `&&` and `||` drop only the candidates opened before them; `<=` and `<<` do not open one), and slangc 2026.13.1 dropped the parentheses around a comparison that is an argument (2026.20 keeps them: 30 shapes validate in naga without the wrapper, measured in m4.z; the wrapper stays because `gust::slang` runs whatever `slangc` is on `PATH` and 13.1 fails 13 of the 30). So `f(a < b, c > d)`, `(a < b) ^ (c > d)` (a `__gust_xor` call) reached WGSL under 13.1 as `f(a_0 < b_0, c_0 > d_0)`, which naga and wgpu refuse. A `<` comparison (through parentheses, or as the right operand of `&&` or `||`) that is an element of a call, an array literal or the operands of `^` (array literals are wrapped the same way, though no accepted program can use one yet), and is followed by another element, is emitted as `__gust_keep(a < b)`: an identity `bool` helper, emitted only in a module that has such a list (same gating as `__gust_xor`), whose own parentheses keep the `<` away from the later `>`. The last element needs nothing, because the closing `)` ends the candidate. Operators (`==`, `&`, shifts), `if` conditions and statements keep their parentheses, and slangc turns `&&` and `||` in an argument into a branch, so they need nothing today; that is slangc's choice, not the lexer's, which is why the right operand of `&&` and `||` is wrapped anyway. Hoisting the comparison into a `let` does not work: slangc re-inlines it. `KeepUsage` and `emit_list` share `needs_keep`, so change them together.

Integer literals (fx.wgsl): slangc types a bare decimal above `i32::MAX` as `int64_t`, which WGSL and SPIR-V validation refuse next to a 32-bit operand. The dialect has no 64-bit integers, and Rust types an unsuffixed literal of 2^31 or more only as `u32`, so `integer_literal` in `slang/mod.rs` spells it `uint(..)` (`2147483648u` and `uint(2147483648)` compile alike; hexadecimal arrives as decimal digits). Bare digits stay for values up to `i32::MAX`, for a negated literal (`-2147483648` is `i32::MIN` and slangc types it right) and for a value above `u32::MAX`, which stays loud at shader creation instead of being truncated by a `uint(..)`. Vector operands (M6) call the same function.

Content key, embedding and export records (M4, D45, D46; `crates/gust-macros/src/expand/artifact.rs`): once a kernel's Slang text is final, and before the CPU twin is generated, the macro computes `content_key(entry_point, clean_slang)`: FNV-1a 64 over the entry point, one NUL byte and the clean text (no `#line` directives, no line-ending normalisation), as 16 hex digits. The function is a byte-for-byte copy of `gust::artifact::content_key`; both crates assert the same golden strings, so change neither alone. When `gust-artifacts/<key>.wgsl` and `<key>.wgsl.reflection.json` both exist under `CARGO_MANIFEST_DIR` the kernel's `artifacts` is the one-element slice built from `include_bytes!` and `include_str!` of `concat!(env!("CARGO_MANIFEST_DIR"), "/gust-artifacts/..")`, with `require_artifact(true)` (the module gets one `require_manifest(<manifest exists>)` for all its kernels, at the first kernel with a pair); with neither it is `&[]` and `require_artifact(false)`; with one of the two it is a coded `compile_error!` (E0711) at the kernel naming the missing file and the one to delete, never a silent `&[]`, except in export mode, where a half pair counts as absent so that `cargo gust build` can repair it (E0712 and E0713 are the export write and package-name errors). An existing `gust-artifacts/manifest.json` is included once per module so cargo tracks it. The macro never reads `GUST_PROFILE`: the strict checks live in `gust::profile`. With `GUST_EXPORT_DIR` set and non-empty, each kernel also writes `<dir>/<CARGO_PKG_NAME>/<key>.slang` (the clean text, exact bytes) and `<key>.kernel.json` (schema 1, sorted keys, no timestamp or path; layouts are the macro's StorageV1 claim, `null` for an element type it cannot describe); `write_records` refuses any record that holds generated CPU twin forms (`TWIN_TEXT`: the `cfg`, the `gust::cpu::` paths and the reserved prefixes; a user name such as `CpuDevice` or `gust_dual` is not twin text), and the export keeps `require_artifact(<present>)`. Test these with `expand_in` and an `Environment` of your own, never by changing the process environment; the `kernel.json` goldens live in `crates/gust-macros/tests/golden` and are blessed by `cargo xtask bless`.

Read [semantic mappings](references/semantic-mappings.md) for risky translations. Use `slang-language` only for target compilation issues and `gpu-vertical-slice-verification` for an end-to-end claim. Report frontend, shader and runtime evidence separately.

Identifier renaming (M6 plan 2.5; `crates/gust-macros/src/slang/collisions.rs`): a user name in the sorted `COLLISIONS` table (Slang keywords and types that slangc refuses in some position, and names GUST's own text uses) is emitted as `__gust_r_<name>` at every name site through `slang::emit_ident`; a raw prefix is stripped first and every other name is unchanged. E0901 denies the `__gust_`, `__gpu_` and `__Gust` prefixes, so the rule is injective and its inverse is deleting `__gust_r_`. Descriptors (`ParameterDescriptor.name`, `StructFieldLayout.name`) carry the emitted names; `rust_type` keeps the Rust spelling. `gust::slang::annotate_diagnostics` deletes the prefix from slangc messages; naga and wgpu messages keep slangc's mangled `_gust_r_<name>_N`. A test that needs a Slang-only error cannot use `new` any more: take the emitted Slang text with the prefix deleted (`unrenamed()` in `crates/gust/tests/diagnostics.rs`).

Uniforms (M6, D57; `crates/gust-macros/src/uniform.rs`, `tests/fixtures/uniforms.*`): a `Uniform<T>` (alias `ConstantBuffer<T>`) parameter lowers to `[[vk::binding(g, b)]] ConstantBuffer<T> name;` and is read field by field (`name.field`, `name.nested.field`); the whole value is never copied or passed (GUST-E0321, since slangc crashes on WGSL when a constant-buffer struct is copied whole and the twin would accept what the GPU cannot). `T` is a struct of the same module (E0206) that no storage buffer reaches (E0207), holds no `Mat2` or `bool` (E0205) and has no implicit padding in its `Std140V1` layout (scalars 4/4, `Vec2` 8/8, `Vec4` 16/16, `Mat4` 64/16, a struct rounded up to 16 in size and alignment): a gap before a field or a tail is GUST-E0209 and names the explicit `f32` padding fields to write (a gap or tail that `#[repr(C)]` has too is GUST-E0208 first). The macro works by name, so it computes this layout from scalar, vector, `Mat4` and module-struct field types, declares the reached structs `#[repr(C, align(16))]` and leaves the rest to the `const` offset assertions of the expansion. The generated typed call names `Resource::Kind` (`::gust::kind::Storage` or `::gust::kind::Uniform`) in every bound and counts storage plus uniform parameters in its arity assertion; the CPU twin builds `::gust::Uniform(..)` from `cpu::read_uniform`.
