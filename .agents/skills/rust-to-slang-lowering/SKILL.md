# Rust to Slang lowering

Emit Slang directly from the validated syn AST. Retain the module boundary. Small scoped symbol/type/binding tables and an emitter are appropriate; a custom instruction IR is future/optional and requires an explicit architecture request.

1. Read the validator, emitter and closest accepted fixture. State the source-to-target rule before editing.
2. Preserve evaluation order, scope, signedness, width, precedence and control flow. Map only validated intrinsics/calls.
3. Keep shader names, resource bindings and runtime metadata deterministic and generated from one contract.
4. Add a focused source -> Slang assertion, compile affected targets, and execute a nontrivial semantic case when behavior changes.

Operators whose Rust meaning depends on the operand type go through `__gust_*` overload helpers, emitted only when the module uses them, because the macro sees syntax and not types: unary `!` is `__gust_not` (`!` on `bool`, `~` on integers), and `^` and `^=` are `__gust_xor` and `__gust_xor_assign` (`!=` on `bool`, `^` on integers), since WGSL defines `^` only on integers; the `_assign` form takes the place `inout`, so it is evaluated once. `&`, `|`, `&=` and `|=` on `bool` pass through unchanged.

Products and the integer dot (M6, m6.m2; `module_lowering`, `Lowering` and `LoweringScope` in `crates/gust-macros/src/slang/mod.rs`, the table in `slang/mul_table.rs`): the emitter is a set of free functions, so the two per-module flags live in a thread-local set for the span of one `emit_kernel`. A module whose unrawed identifier tokens include `Mat2`, `Mat3` or `Mat4` is *gated*: every `*` is `__gust_mul(a, b)` and every `*=` is `(place = __gust_mul(place, b))`, and the overload table (one line per row of `MUL_PAIRS`, 39 rows) follows the prelude. Slang's `*` on two matrices is component-wise where Rust's is the matrix product, so a matrix product row is `mul(a, b)`; slangc picks the overload by the operand types and types an unsuffixed literal beside a typed operand. The gate is exact because E0203, E0324 and E0102 leave the prelude as the only way the name resolves; ungated modules keep the verbatim `*`, so every golden without a matrix is byte-identical. A `*=` whose place contains a call (anything but names, fields, indexing, arithmetic, `.global_id()` and `.len()`) is E0323: the place would be written twice. The same table generates every `Mul` and `MulAssign` impl of `gust::math` (`gust_mul_impls!` in `crates/gust-macros/src/mul_impls.rs`, invoked once in `crates/gust/src/math.rs`; `math.rs` writes no product by hand, a source test pins it), and `crates/gust/tests/diagnostics.rs` compiles every row on both targets, so adding a type means one new row in one file. A module that contains a `dot` token sends every `.dot` through `__gust_dot`: Slang's `dot` on an integer vector is `OpSDot`/`OpUDot`, which needs SPIR-V `Capability DotProduct` and is refused by naga's SPIR-V reader, so the integer overloads are the sum of the component products. The macro cannot tell a float `dot` from an integer one, so a float-only module takes the overloads too (its SPIR-V is byte-identical, its WGSL calls a helper). A product in a future `const` or array length must not become a `__gust_mul` call, because Slang cannot use a call as a size: the slice that adds constants lowers a product there with the plain `*`.

Negation (M6, m6.n; `slang/neg_table.rs`, `Lowering::neg`, the `Unary` arm of `emit_expression`): slangc's WGSL for a unary `-` on a matrix is `mat4x4<f32>(0) - m`, which naga refuses (SPIR-V is `OpFNegate` and passes), and `0.0 - m` would turn a `+0` lane into `+0`. A module gated by the matrix tokens (the same exact gate as `__gust_mul`) lowers every unary `-` whose operand is not a literal to `__gust_neg(a)`, and the table of overloads (10 rows: `f32`, `i32`, `Vec2/3/4`, `IVec2/4` as slangc's `-a`, `Mat2/3/4` as `a * -1.0`) follows the `__gust_mul` table. Under IEEE arithmetic `a * -1.0` is bit-identical to negation for every non-NaN value, `-0` included (a device that drops the sign of a zero, which Vulkan allows without `SignedZeroInfNanPreserve`, or flushes a subnormal in a multiply, may differ from the twin's sign flip: D39, measured by the `vectors` GPU test), and slangc emits it as a per-column product (WGSL) or `OpVectorTimesScalar` (SPIR-V), both of which pass naga and `spirv-val`. A negated literal keeps the plain `(-2.0)` / `(-3)`; ungated modules keep `(-a)`, so every golden without a matrix is byte-identical. Slangc's WGSL for a float vector `-v` is `vec(0) - v` (a `+0` lane stays `+0`, D39); `-v` is not scaled, so it means the same in every module. `gust::math` has `Neg` for `Vec2/3/4`, `IVec2/4` (lane by lane, so it follows the defining crate's overflow mode like a scalar) and the matrices, and every one has a row. A `-` in a future `const` or array length must stay a plain `-`, as the product must (Slang cannot use a call as a size).

Division (M6, m6.dv, D74's cure; `slang/div_table.rs`, `division_helper`, `DivisionUsage` and the `Binary` arms of `emit_expression` in `slang/mod.rs`): slangc 2026.20 folds integer `/` and `%` and refuses a divisor that folds to zero (`E30002`), even in code no invocation runs (a dead branch, `7 / (i * 0)`, `i - i`, the first iteration of an unrolled loop, a wrapping `/=`). The same operation behind a call compiles in every probed shape on WGSL and SPIR-V, so every `/`, `%`, `/=` and `%=` whose divisor is not a literal (a literal, negated or parenthesised or not, stays a plain operator: the validator rejects a literal zero, E0317) is `__gust_div(a, b)`, `__gust_rem(a, b)`, `__gust_div_assign(place, b)` or `__gust_rem_assign(place, b)`, the `_assign` forms with the place `inout` so it is evaluated once. Ungated: the macro sees syntax and not types, so any module with such an operator gets the overloads (`/` in `DIV_ROWS`: 3 scalars, 8 vector types with themselves and with their scalar; `%` in `REM_ROWS`: the 3 scalars, because `gust::math` has no `Rem` on a vector), each family once, after the `__gust_neg` table, whose body is the plain operator with no `[noinline]` (slangc inlines it in SPIR-V; the WGSL keeps `_gust_div_0(..)`, whose body is the plain `/`, so the WGSL results of D39/KM-01 to KM-03 hold unchanged and the cost is noise, spike m6.s1). A module with a literal divisor only keeps its text; a module with any other divisor has the table in its golden. A division in a future `const` or array length must stay a plain operator (Slang cannot use a call as a size), as the product and the negation must.

Wrapping methods (M7, m7.w; `wrapping_arity` in `validate/mod.rs`, the `MethodCall` arm after the `is_math_method` one in `emit_expression`, `is_pure_place`): `a.wrapping_add(b)`, `a.wrapping_sub(b)` and `a.wrapping_mul(b)` are the plain Slang `(a + b)`, `(a - b)` and `(a * b)`, and `a.wrapping_neg()` is `(0 - a)`. The macro sees no types, so the form must be right for `u32` and `i32` alike: slangc types the literal `0` as the operand's own type, while a unary `-` on a `u32` reaches WGSL as `- x`, which naga refuses (probed on 2026.20; `~x + 1` also works but reads worse). WGSL integer arithmetic wraps modulo 2^32 (section 6.2.3), so the plain operator is the whole lowering and the twin needs nothing: the preserved Rust calls the std method. A wrapping `*` is never `__gust_mul`, even in a module that names a matrix (test `wrapping_methods_lower_to_the_plain_operators_even_in_a_matrix_module`), and `wrapping_div` and `wrapping_rem` are deliberately not accepted (a zero divisor has no wrapped result). A wrong argument count is E0304; any other method with arguments is E0325 (listing the accepted methods, `ACCEPTED_METHODS`), without arguments E0305. A new accepted method goes into `wrapping_arity` or the validator's match, `emit_expression`, `is_pure_place` if it is arithmetic on its operands, `ACCEPTED_METHODS` and docs/DIAGNOSTICS.md together.

Comparison arguments and `__gust_keep` (fx.wgsl): WGSL reads `name < .. >` as a template list (a `<` after an identifier opens a candidate and any later `>` on the same nesting depth closes it, whatever follows the `>`, so `>=` and `>>` close one too; a `)` or `]` drops the candidates opened inside its brackets, `=`, `:`, `;` and `{` drop all of them, and `&&` and `||` drop only the candidates opened before them; `<=` and `<<` do not open one), and slangc 2026.13.1 dropped the parentheses around a comparison that is an argument (2026.20 keeps them: 30 shapes validate in naga without the wrapper, measured in m4.z; the wrapper stays because `gust::slang` runs whatever `slangc` is on `PATH` and 13.1 fails 13 of the 30). So `f(a < b, c > d)`, `(a < b) ^ (c > d)` (a `__gust_xor` call) reached WGSL under 13.1 as `f(a_0 < b_0, c_0 > d_0)`, which naga and wgpu refuse. A `<` comparison (through parentheses, or as the right operand of `&&` or `||`) that is an element of a call, an array literal or the operands of `^` (array literals are wrapped the same way, though no accepted program can use one yet), and is followed by another element, is emitted as `__gust_keep(a < b)`: an identity `bool` helper, emitted only in a module that has such a list (same gating as `__gust_xor`), whose own parentheses keep the `<` away from the later `>`. The last element needs nothing, because the closing `)` ends the candidate. Operators (`==`, `&`, shifts), `if` conditions and statements keep their parentheses, and slangc turns `&&` and `||` in an argument into a branch, so they need nothing today; that is slangc's choice, not the lexer's, which is why the right operand of `&&` and `||` is wrapped anyway. Hoisting the comparison into a `let` does not work: slangc re-inlines it. `KeepUsage` and `emit_list` share `needs_keep`, so change them together.

Integer literals (fx.wgsl): slangc types a bare decimal above `i32::MAX` as `int64_t`, which WGSL and SPIR-V validation refuse next to a 32-bit operand. The dialect has no 64-bit integers, and Rust types an unsuffixed literal of 2^31 or more only as `u32`, so `integer_literal` in `slang/mod.rs` spells it `uint(..)` (`2147483648u` and `uint(2147483648)` compile alike; hexadecimal arrives as decimal digits). Bare digits stay for values up to `i32::MAX`, for a negated literal (`-2147483648` is `i32::MIN` and slangc types it right) and for a value above `u32::MAX`, which stays loud at shader creation instead of being truncated by a `uint(..)`. Vector operands (M6) call the same function.

Untyped locals (m6.z2, D86): the `Stmt::Local` arm of `emit_statement` writes `var` for a local without an annotation, and Slang types `var x = 7;` as `int` while rustc may infer `u32` from the later uses (`d /= y` with `y >= 2^31`: Rust 0, GPU `0xFFFFFFF9`). The emitter is stateless and has no typer, so the validator refuses an unannotated `let` whose initializer is only unsuffixed integer literals (GUST-E0326) and the arm needs no inference. An annotated local is declared with its Slang type (`uint d = ...`), a suffixed literal is `uint(..)`/`int(..)`; the GPU test `typed_locals` (numeric fixture) pins the typed path at the edge. Do not teach the emitter to guess a type from a literal.

Content key, embedding and export records (M4, D45, D46; `crates/gust-macros/src/expand/artifact.rs`): once a kernel's Slang text is final, and before the CPU twin is generated, the macro computes `content_key(entry_point, clean_slang)`: FNV-1a 64 over the entry point, one NUL byte and the clean text (no `#line` directives, no line-ending normalisation), as 16 hex digits. The function is a byte-for-byte copy of `gust::artifact::content_key`; both crates assert the same golden strings, so change neither alone. When `gust-artifacts/<key>.wgsl` and `<key>.wgsl.reflection.json` both exist under `CARGO_MANIFEST_DIR` the kernel's `artifacts` is the one-element slice built from `include_bytes!` and `include_str!` of `concat!(env!("CARGO_MANIFEST_DIR"), "/gust-artifacts/..")`, with `require_artifact(true)` (the module gets one `require_manifest(<manifest exists>)` for all its kernels, at the first kernel with a pair); with neither it is `&[]` and `require_artifact(false)`; with one of the two it is a coded `compile_error!` (E0711) at the kernel naming the missing file and the one to delete, never a silent `&[]`, except in export mode, where a half pair counts as absent so that `cargo gust build` can repair it (E0712 and E0713 are the export write and package-name errors). An existing `gust-artifacts/manifest.json` is included once per module so cargo tracks it. The strict artifact checks live in `gust::profile`, not in the macro, which reads `GUST_PROFILE` only for the build's capabilities and the `cpu` target (M8). With `GUST_EXPORT_DIR` set and non-empty, each kernel also writes `<dir>/<CARGO_PKG_NAME>/<key>.slang` (the clean text, exact bytes) and `<key>.kernel.json` (schema 1, sorted keys, no timestamp or path; layouts are the macro's StorageV1 claim, `null` for an element type it cannot describe); `write_records` refuses any record that holds generated CPU twin forms (`TWIN_TEXT`: the `cfg`, the `gust::cpu::` paths and the reserved prefixes; a user name such as `CpuDevice` or `gust_dual` is not twin text), and the export keeps `require_artifact(<present>)`. Test these with `expand_in` and an `Environment` of your own, never by changing the process environment; the `kernel.json` goldens live in `crates/gust-macros/tests/golden` and are blessed by `cargo xtask bless`.

Shapes and the fragment entry point (MX, D61, D63, D120, D127; `crates/gust-macros/src/profile/{mod,grid,pixel}.rs`, `expand/mod.rs`, `tests/fixtures/pixel.{rs,slang}`): the stage-specific text comes from the `StageProfile` of the kernel's shape, never from a test of the shape in the emitter. A kernel is built with the module's profile (`GRID`) unless it pins `#[kernel(shape = pixel)]`; a pin the classifier accepts swaps in `PIXEL` for that kernel only (`profile_of` in `expand/mod.rs`), so one module may hold both shapes, and the emitter recognises a sibling kernel by its attribute alone, never by parsing its options under this kernel's profile, which may refuse them (the mx.p1b fix, comment at `slang/mod.rs:609`: an explicit-`workgroup_size` `grid` kernel beside a `pixel` one failed with E0707). The `pixel` entry is `[shader("fragment")] void gpu_<module>_<kernel>(float4 __gust_pos : SV_Position)`. Its prologue is `uint __gust_linear = ((uint(__gust_pos.y) * 8192u) + uint(__gust_pos.x));` and `uint3 <id> = uint3(__gust_linear, 0u, 0u);`, then the usual `GetDimensions` length reads, so the body's `id.x` is the element index. Outputs are not `SV_Target`s: they stay `RWStructuredBuffer`s at their ordinary slots and `out[i] = v` is emitted as it is (the emitter never calls `lower_output_write`, and both profiles answer `None`; D120), the entry returns nothing, and the host's one never-written attachment exists only to give the rasteriser a frame. No `pixel` kernel reads a uniform for its row width: 8192 is in the text and so in the content key (`ROW_WIDTH` in `profile/pixel.rs` and `gust::PIXEL_ROW_WIDTH`; `the_row_width_in_the_slang_text_is_the_constant_the_host_uses` in `crates/gust/tests/pixel_twin.rs:152` compares the emitted text with the constant). The descriptor and the record carry `workgroup_size` `[1, 1, 1]` for a fragment. The kill rule (D88): a `Shape` test inside `emit_statement` or `emit_expression`, or a profile hook that needs the syn body, means the interface is wrong, so redesign it before adding a third shape. Add a profile answer and a fixture kernel, run the golden diff (`cargo xtask bless` only after reading it), and check that every `grid` golden, artifact and `export-artifacts --compare` hash stays equal.

Textures and samplers (MX, D64, D90, D91; `crates/gust-macros/src/slang/texture.rs` is the one table the validator, the emitter and the expander read, `tests/fixtures/textures.{rs,slang}`): `Texture2D<T> t` is `Texture2D<T> t;`, `StorageTexture2D<F>` is `[format("<Slang name of F>")] RWTexture2D<T> t;` (for example `r32f`; `r32ui` and `r32i` are the other two), `WriteTexture2D<F>` is `[format("<Slang name of F>")] WTexture2D<T> t;` (for example `rgba32f`, `rg32i`; the table is `slang/texture.rs`) and `Sampler` is `SamplerState s;`, each with its `[[vk::binding(n, 0)]]` in parameter order beside the buffers (the `ParameterFlavor`s `SampledTexture`, `StorageTexture`, `WriteTexture` and `Sampler`). `t.load(x, y)` is `t[uint2(x, y)]`, `t.store(x, y, v)` is `t.Store(uint2(x, y), v)`, `t.sample(s, u, v)` is `t.SampleLevel(s, float2(u, v), 0.0)` (level 0 only, D92), and `t.width()` and `t.height()` read `__gpu_width_t` and `__gpu_height_t`, set in the prologue by `GetDimensions`. A sampler is only ever a parameter name (E0733), a texture only the receiver of a method (E0736), so the emitter never builds one. The format table of D62 and D120 is checked per shape (a wide `read_write` format is refused, so `WriteTexture2D` exists), and the codes are GUST-E0731 to E0736 (E0732 and E0734 are pinned by unit tests only, because rustc adds its own error beside them).

Read [semantic mappings](references/semantic-mappings.md) for risky translations. Use `slang-language` only for target compilation issues and `gpu-vertical-slice-verification` for an end-to-end claim. Report frontend, shader and runtime evidence separately.

Identifier renaming (M6 plan 2.5; `crates/gust-macros/src/slang/collisions.rs`): a user name in the sorted `COLLISIONS` table (Slang keywords and types that slangc refuses in some position, and names GUST's own text uses) is emitted as `__gust_r_<name>` at every name site through `slang::emit_ident`; a raw prefix is stripped first and every other name is unchanged. E0901 denies the `__gust_`, `__gpu_` and `__Gust` prefixes, so the rule is injective and its inverse is deleting `__gust_r_`. Descriptors (`ParameterDescriptor.name`, `StructFieldLayout.name`) carry the emitted names; `rust_type` keeps the Rust spelling. `gust::slang::annotate_diagnostics` deletes the prefix from slangc messages; naga and wgpu messages keep slangc's mangled `_gust_r_<name>_N`. A test that needs a Slang-only error cannot use `new` any more: take the emitted Slang text with the prefix deleted (`unrenamed()` in `crates/gust/tests/diagnostics.rs`).

Uniforms (M6, D57; `crates/gust-macros/src/uniform.rs`, `tests/fixtures/uniforms.*`): a `Uniform<T>` (alias `ConstantBuffer<T>`) parameter lowers to `[[vk::binding(g, b)]] ConstantBuffer<T> name;` and is read field by field (`name.field`, `name.nested.field`); the whole value is never copied or passed (GUST-E0321, since slangc crashes on WGSL when a constant-buffer struct is copied whole and the twin would accept what the GPU cannot). `T` is a struct of the same module (E0206) that no storage buffer reaches (E0207), holds no `Mat2` or `bool` (E0205) and has no implicit padding in its `Std140V1` layout (scalars 4/4, `Vec2` 8/8, `Vec4` 16/16, `Mat4` 64/16, a struct rounded up to 16 in size and alignment): a gap before a field or a tail is GUST-E0209 and names the explicit `f32` padding fields to write (a gap or tail that `#[repr(C)]` has too is GUST-E0208 first). The macro works by name, so it computes this layout from scalar, vector, `Mat4` and module-struct field types, declares the reached structs `#[repr(C, align(16))]` and leaves the rest to the `const` offset assertions of the expansion. The generated typed call names `Resource::Kind` (`::gust::kind::Storage` or `::gust::kind::Uniform`) in every bound and counts storage plus uniform parameters in its arity assertion; the CPU twin builds `::gust::Uniform(..)` from `cpu::read_uniform`.

Map functions (M7, m7.a1, D60; `crates/gust-macros/src/expand/map.rs`, `tests/fixtures/map.{rs,slang}`): `#[gpu]` on a free scalar function builds a synthetic module (the user's function as a private helper, copied as written, and the generated `map_kernel`) and hands it to the ordinary `expand_validated`, with the host functions as `extra`; there is no second pipeline. The kernel is the grid-stride form, workgroup 256, every buffer bound `Independent`: the parameters are the user's names as `StructuredBuffer<elem>` plus `mut __gust_out`, `n` is `__gust_out.len()`, `rounds = n / 16776960 + (n % 16776960 != 0)` (the ceiling is `gust::map::CEILING`, pinned by a test), each invocation runs `j = id.x + round * 16776960` under `if j < n`, and an input buffer of length 1 is read at index 0 (a `Broadcast`). `bool` is a `u32` word (`x[i] != 0u32` in, `__gust_r as u32` out). Slang has no `if` as a value (GUST-E0811), so the kernel uses mutable locals and casts. Under `GUST_PROFILE=cpu` the host functions name only `::gust::cpu`, never `::gust_wgpu` (check-cpu-target E-b scans the binary), and `__gust_map_cpu_chunk` is emitted for the parallel CPU map of m7.c. Golden: `map.slang`, one `// ==== kernel <name> ====` section per fixture function.

Workgroup memory, barriers and derived ids (M7, m7.g1; `ParameterFlavor` and its `parameter_flavor` in `slang/mod.rs`, `validate/barrier.rs`, `expand/mod.rs`, `tests/fixtures/workgroup.{rs,slang}`): the flavor of a parameter type (`Value`, `LocalId`, `GroupId`, `Workgroup`) decides where it goes. `in_descriptor()` is false for the last three, so they have no descriptor entry, no binding, no argument of the typed call, no host-call argument and no field of the record; the layout-assertion index is counted over descriptor parameters only. `Workgroup<[T; N]>` lowers to a module-scope `groupshared T name[N];`; `LocalId`/`GroupId` (and `SV_GroupThreadID`/`SV_GroupID`) lower to a local `uint3` built from the `SV_DispatchThreadID` parameter and the declared workgroup size with `%` and `/` per axis, so the helper and the reflection schema are unchanged; `workgroup_barrier();` is `GroupMemoryBarrierWithGroupSync();`. The CPU twin of a kernel that only reads the ids derives them the same way and stays; a kernel with a `Workgroup` parameter or a barrier carries `cpu = "unsupported"` and under `GUST_PROFILE=cpu` has no `Run` implementation. The total of the `Workgroup` arrays (4 bytes per scalar, 8 for a 2-wide vector, 16 for a 3- or 4-wide one) is checked against 16384 at expansion (GUST-E0718).

`par_for!` and the three-axis guard (M7, m7.p, D103, and m7.d, D102; `crates/gust-macros/src/par_for.rs`, `tests/fixtures/par_for.{rs,slang}`): the macro goes through the map generator's machinery (`element_types` in `expand/map.rs`, then `expand_validated`) and not through a second emitter. It lowers the body once under the placeholder module `__gust_pf`, takes the `content_key` of that clean Slang text, and expands for real as `__gust_pf_<hash16>`, so two spellings of one body are one kernel and the file and line stay out of the key. The extents and the scalar bindings travel in one `Uniform<__GustExtent>` (a `bool` as a `u32` word), and every buffer is `Independent`. The kernel body runs inside `if x < extent.x && y < extent.y && z < extent.z` over all three axes whatever the loop's arity, because a `workgroup_size` taller or deeper than the loop starts invocations on the unused axes too (their extent is 1); a guard that names fewer axes passes on the GPU, where the extra invocations store the same value, and fails only on the twin, so the twin tests `a_workgroup_taller_than_the_loop_runs_each_element_once` and `a_workgroup_deeper_than_the_loop_runs_each_cell_once` are the check. A malformed call is GUST-E0719 and a name the expansion defines (`run`, `launch`, `launch_default`, `DESCRIPTOR`, `__gust_` names) is GUST-E0720. The launch is `dispatch_extent`, and `gust::Extent` rounds each axis up to the workgroup and caps the rounded product at 2^32.

Subgroup operations (M8, m8.s, D140; `emit_subgroup_call` and `subgroup_helper_text` in `slang/mod.rs`, `tests/fixtures/subgroup.{rs,slang}`): add/mul/min/max are `WaveActiveSum/Product/Min/Max`, all/any `WaveActiveAllTrue/AnyTrue`, ballot `WaveActiveBallot` (a `uint4`), broadcast_first `WaveReadLaneFirst`, shuffle `WaveShuffle`, the exclusive scans `WavePrefixSum/Product`, size `WaveGetLaneCount()` and lane `WaveGetLaneIndex()`. A broadcast with an integer-literal lane is `WaveBroadcastLaneAt`; any other lane is `WaveReadLaneAt` (slangc E40012). The emitter has no type information, so the type-dependent forms are per-kernel overload helpers like `__gust_xor`, emitted only for a kernel that calls them: `__gust_subgroup_and/or/xor` (the `int` overload goes through `asuint`/`asint`, because DX12 has no signed reduction), `__gust_subgroup_inclusive_add/mul` (the prefix operation combined with the value), and `__gust_subgroup_count` (the popcount of the ballot words). `elect` is `WaveGetLaneIndex() == WaveReadLaneFirst(WaveGetLaneIndex())` because naga has no `subgroupElect`. Arguments go through `emit_list`, which handles the `__gust_keep` problem of a less-than argument.

Variants, targets and the descriptor (M8, D137, D139, D145; `expand/mod.rs` `mod variant`, `expand/artifact.rs`): `variant::lower` rewrites each `#[variant(of = k, requires(..))]` into a `#[kernel(<k's workgroup size and shape>, <cpu option>, requires(<its own>))]` before the validator, so a variant body goes through the ordinary kernel lowering and has its own entry point (`gpu_<module>_<function>`), content key and record; the kernel keeps one handle, one typed call and one CPU twin (the portable body's). The build selects the body whose `requires` is the largest set contained in the capabilities of `GUST_PROFILE`, and only that body's entry point, Slang, artifacts, `variant` and `requires` go into the descriptor. The descriptor is written with the hidden `gust::__gust_descriptor!` constructor (every field by name), never a struct literal, because `KernelDescriptor` is `#[non_exhaustive]` (B1), and its `target` is the module's route (`Target::Cpu` for a CPU-routed module or `GUST_PROFILE=cpu`, else `Gpu`). The macro implements the hidden marker `gust::target::GpuKernel` for every kernel not routed to the CPU: that impl is what makes a routed kernel an E0277 on `HeadlessDevice`, so a lowering change that drops or adds it changes the call-site rule, not only the text. The route variable `GUST_ROUTE__<package>__<tag>` is tracked with `option_env!`, so changing it recompiles the crate; `gust::routes::variable_name` is copied byte for byte into the macro and a golden table pins both. An export record is schema 4 only for a variant or a body with `requires`; every other record keeps its schema bytes. Fixtures: `tests/fixtures/{variant,subgroup}.{rs,slang}`, `crates/gust-macros/src/tests/{variant,routes}.rs`.

M9 lowering (D154 to D162, D170; goldens `tests/fixtures/{methods,methods_mut,enums,traits,generics}.{rs,slang}`): an `impl S` function with a receiver is a member of the Slang struct (`&mut self` is `[mutating]`, an associated function is `static`, the receiver is `this`, and a call keeps the method syntax). A field-less `enum` is `enum E : uint { .. }` (or `int` for `#[repr(i32)]`), and a statement `match` is a `switch`; a value `match` is `T x;` followed by a `switch` whose arms assign (an arm that names `x` assigns a `__gust_match_<n>_<k>` temporary). A tuple is `Tuple<A, B>`, built with `makeTuple` and read as `._N`. An array is `T[N]`, a literal is `{ a, b }`, an index is `a[uint(i)]`, and a repeat evaluates its operand once into `__gust_rep_<k>` (for `N` above 16 a `__gust_fill_<k>` loop fills it). A non-capturing closure is hoisted to a function `__gust_cl_<owner>_<n>` and called by that name. A trait is an `interface` and `impl T for S` is `extension S : T`; a trait path call is rewritten to the method call before emission. A generic helper or method is `T f<T : A & B>(T t)` and slangc specialises it. The names `Tuple`, `makeTuple`, `this`, `interface`, `extension` and the 46 interface names of Slang's standard module are in the rename table (`__gust_r_<name>`, `STDLIB_INTERFACES` in `slang/collisions.rs`), which changes the text and so the artifact content key (a 0.2.0 break, B4). With the feature `spirv-route` on, `slang/guards.rs` makes the emitter add the guards naga adds on the WGSL route: an index clamp `min(uint(i), N - 1)` only where the length is known (a typed local or parameter, an array field by name, `Workgroup<[T; N]>`; never a buffer index), `__gust_div` and `__gust_rem` for a zero divisor and signed overflow, and workgroup zeroing. Evaluation order is the risk of this area: Slang and Rust differ for the place and the value of an assignment, a `for` start and end, and (changed between slangc 2026.20 and 2026.21) the index and value of an indexed assignment, so the validator refuses those forms (GUST-E0421) instead of relying on a version. Measure an order claim on the pinned slangc and with rustc before writing it.
