# Direct emission rules

These are design constraints for extending the existing dialect, not a claim that every construct is currently supported.

| Rust source | Emission rule / rejection condition |
|---|---|
| `u32`, `i32`, `f32` | Use deliberate target-width mapping (`uint`, `int`, `float`); reject unsupported widths. |
| `usize`, unsuffixed literals | Require a documented restricted typing/range rule; host pointer width is not GPU index width. |
| Binary/unary expressions | Parenthesize structurally or use an explicit precedence table; preserve signed comparisons, short circuit and unary minus. |
| Casts | Check Rust versus Slang behavior, especially float-to-int, truncation and overflow. Reject unsupported semantics. |
| Locals and shadowing | Maintain lexical scopes; mangle collisions and reserved target names deterministically. |
| Function calls | Resolve allowlisted module helpers/intrinsics, arity and types; do not stringify an arbitrary Rust path. |
| Method syntax | Map only known receiver/intrinsic pairs; `.len()` is not an arbitrary shader method. |
| Index read/write | Enforce buffer access, index type and host length contract; write only to writable resources. |
| `if`, blocks, tail expressions | Rust expressions may yield values; emit a compatible value/temporary or reject. Do not lose the final expression or branch. |
| Loops, break/continue, returns | Support only explicitly implemented forms; preserve exits and return values. |
| Vector and matrix types (`gust::math`) | By name, from the prelude only: `Vec2/3/4` to `float2/3/4`, `IVec2/4` to `int2/4`, `UVec2/3/4` to `uint2/3/4`, `Mat2/3/4` to `float2x2/3x3/4x4` (`crates/gust-macros/src/math_types.rs` is the one table). A struct may not reuse these names (E0203), and a qualified path to one (`super::Mat4`) is E0324. `Vec3`, `UVec3` and `Mat3` are locals and helper values only (E0204 as a struct field or resource element). A struct whose fields leave implicit padding is E0208. In a module that names `Mat2/3/4`, `a * b` is `__gust_mul(a, b)` and `p *= b` is `(p = __gust_mul(p, b))` (E0323 if the place `p` contains a call); a module that contains a `dot` lowers every `.dot` to `__gust_dot`, whose integer overloads are a sum of products (SPIR-V `OpSDot` needs a capability naga refuses; the macro has no types, so a float-only module takes the overloads too, with the same SPIR-V). |
| Vector and matrix constructors | `Vec4::new(a, b, c, d)` is `float4(a, b, c, d)`, `Vec4::splat(s)` is `float4(s)`, `Mat4::IDENTITY` is the rows constructor of the identity. Slang's matrix constructor takes rows and Rust matrices are column-major, so `Mat4::from_rows(r0, r1, r2, r3)` is `float4x4(r0, r1, r2, r3)` and `Mat4::from_cols(c0, c1, c2, c3)` is `transpose(float4x4(c0, c1, c2, c3))`. These are the only multi-segment paths accepted; any other is E0308 (value) or E0302 (call), with the argument count checked (E0304). |
| Vector and matrix methods | A swizzle `v.xy()` (two to four of `xyzw`) is `v.xy`; `a.dot(b)` is `__gust_dot(a, b)` (m6.m2; see the vector and matrix types row); `m.mul_vec4(v)` and `a.mul_mat4(b)` are `mul(m, v)` and `mul(a, b)` (M x v, written order); `m.transpose()` is `transpose(m)`. `*` on a matrix is lowered by m6.m2 (`__gust_mul`, same row); the `vectors` golden uses methods and the `products` golden uses operators. Slang's `dot` on an integer vector is `OpSDot`/`OpUDot` with `Capability DotProduct` (measured on slangc 2026.13.1 and 2026.20), which spirv-val accepts and naga's SPIR-V reader refuses (`UnsupportedCapability(DotProduct)`), so the integer overloads of `__gust_dot` are a sum of products; the `vectors` golden keeps one such `dot` in the helper `integer_dots`. |
| Unary minus on a matrix | In a module that names a matrix, a unary `-` on a non-literal is `__gust_neg(x)` (`crates/gust-macros/src/slang/neg_table.rs`, one data table): scalars and vectors as `-a`, matrices as `a * -1.0`, because slangc emits `matN(0) - m` for `-m`, which naga refuses on WGSL (m6.n). A bare literal operand stays `-3`; a module that names no matrix keeps the plain `-`. |
| Integer `/` and `%` | Every `/`, `%`, `/=` and `%=` whose divisor is not a literal is `__gust_div(a, b)` or `__gust_rem(a, b)` (the `_assign` forms take the place `inout`; `slang/div_table.rs`), because slangc folds integer division and refuses a divisor that folds to zero (E30002), even in a branch no invocation takes (D77, which retired D74). A literal zero divisor is E0317. |
| Uniform parameters | `u: Uniform<Frame>` (or `ConstantBuffer<Frame>`) is `[[vk::binding(n, 0)]] ConstantBuffer<Frame> u;`, numbered in parameter order with the storage buffers; the element must be a struct of the module (E0206). Reads are `u.field`, one field at a time; a whole-value use, `u.0`, a unary `*` and a `mut` uniform are E0321. Structs a uniform reaches are `#[repr(C, align(16))]` with `Std140V1` const asserts and may not hold `Mat2` or `bool` (E0205) or implicit padding (E0208, E0209), nor also be a storage element (E0207). The twin reads the uniform by copy. The `uniforms` golden is the reference. |
| Colliding names | A user identifier that is a Slang or WGSL keyword, a prelude name or a spelling GUST emits is emitted as `__gust_r_<name>` at every name site through one function, `emit_ident` (a raw `r#` is stripped first); descriptors and host names keep the Rust spelling, `annotate_diagnostics` strips the prefix from slangc messages (naga and wgpu messages keep it), and the `__gust` prefix itself is reserved (E0901). Renaming is collision-only, so a golden without a collision is byte-identical (m6.k). |

Use a typed emission function per node family returning an error for unsupported nodes. Passing syn tokens through Display/ToTokens and replacing strings is not a lowering algorithm. Preserve evaluation order with temporaries where target rules differ; do not duplicate an expression with side effects. Separate Rust host expansion from Slang text emission.

Keep a source-span association for diagnostics using the project's existing mapping or emitted comments; generated line numbers must not be presented as original Rust locations without a mapping. Keep helper ordering and bindings stable.

For numeric changes test integer boundaries, division/shift edge cases and floats with an explicit NaN/infinity/rounding policy. Independent host reference arithmetic can differ from GPU arithmetic; do not use tolerance to conceal a semantic error. Layout comes from the host/shader ABI, not Rust field spelling.

Source guidance checked 2026-09-07: [Rust expressions](https://doc.rust-lang.org/reference/expressions.html), [Slang compilation](https://github.com/shader-slang/slang/blob/master/docs/user-guide/08-compiling.md). Project-specific mapping rules above must be confirmed against existing tests.
