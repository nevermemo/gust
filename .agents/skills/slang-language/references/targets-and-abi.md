# Slang target and ABI notes

Use the repository's pinned slangc first (the version in `SLANG_VERSION` of `crates/cargo-gust/src/slang.rs`, installed by `cargo gust slang install`; `cargo gust doctor` names a different `slangc` first on `PATH`); record `slangc -version`. `cargo xtask slangc` specifies `-entry`, `-stage compute`, `-target`, `-o` and `-matrix-layout-column-major` explicitly and records them in `<out>.command.json`. Extra profile/capability/include arguments are caller supplied after `--`, not guessed; SPIR-V that must keep the descriptor's entry point name needs `-fvk-use-entrypoint-name`, as the Slang bridge passes. Compile WGSL and SPIR-V separately to expose target restrictions.

Project design guidance:
- Use an explicit `(set, binding, access, element layout)` contract shared by emitter and runtime. Slang `[[vk::binding(binding, set)]]` uses binding first; wgpu uses group=set.
- Keep module resources and helper names deterministic. Do not trust compiler auto-allocation to match independently handwritten host layouts.
- A compute entry uses `[shader("compute")]`, `[numthreads(x,y,z)]` and `uint3 ... : SV_DispatchThreadID`. Dispatch counts are workgroups, not invocations.
- Resource types such as `StructuredBuffer<float>` and `RWStructuredBuffer<float>` have different access requirements. Do not translate Rust references into arbitrary shader pointers.
- For portability start with scalar 32-bit storage elements. Rust struct layout alone is not proof of shader layout; verify offsets, alignment, stride and padding. Avoid host bool storage and vec3 packing assumptions.
- Name the matrix layout; never rely on a default. GUST's matrices are column-major (`abi::MATRIX_LAYOUT`): `-matrix-layout-column-major` on every `slangc` command line (`slang::slangc_command`, `reflect::slangc_reflection_command`, `cargo xtask slangc`), `defaultMatrixLayoutMode = SLANG_MATRIX_LAYOUT_COLUMN_MAJOR` in the native reflection helper, and `matrixLayout: "column"` in its schema 2 JSON (written when a resource holds a vector, matrix or constant buffer). The command line of slangc defaults to column-major today and its native API to row-major (measured, M6 spike V1), so a path that leaves it out compiles a different layout without an error; the two paths are compared byte for byte in `crates/gust/tests/reflection.rs`, and `xtask/src/tests/shader.rs` requires the flag in the bodies of those two functions (the whole argument lists are pinned by their own tests in `gust`). Slang's matrix constructor takes rows, so a column-built Rust matrix is `transpose(float4x4(c0, c1, c2, c3))`.
- Vectors and matrices in buffers: `float2`/`float4` (and the int forms) align to 8 and 16, `float4x4` is four 16-byte columns and `float2x2` two 8-byte columns; `float3` and `float3x3` stay out of buffers and uniform structs (3-wide types are locals and helper values only, E0204). A `ConstantBuffer<T>` (`Std140V1`) rounds a struct up to 16, and naga's SPIR-V reader refuses a `float2x2` in one (`UnsupportedMatrixStride`), so `Mat2` is not allowed in a uniform struct. A constant `float2x2` or `float3x3` in SPIR-V crashes pipeline creation on the wgpu route (measured on slangc 2026.20; WGSL and `float4x4` are fine). Slang emits `OpCopyLogical` for copies between aggregates of different layouts and naga's SPIR-V front end refuses it: GUST's SPIR-V targets Vulkan drivers (`cargo xtask spirv-val` and `check-feature artifacts` print an informational count).
- The bundled shader uses four storage bindings and a one-u32 length buffer for a simple explicit ABI. It is a toolchain fixture, not a mandated project ABI.
- Keep a bounds check around reads and writes when dispatch rounds up. Validate all input lengths on the host; checking only output length is insufficient.

WGSL has target-specific restrictions and binding behavior. Check the feature in the pinned Slang version and test the generated WGSL through wgpu validation. Do not work around errors by silently switching targets.
