# wgpu runtime

Consume compiled shader artifacts plus explicit binding/layout metadata; keep syn internals out of the runtime. Match the repository's pinned wgpu API and features.

1. Record adapter name, device type, backend, requested features/limits and shader hash. A missing adapter is unavailable execution, not a passing kernel.
2. Validate shader and pipeline, bind exactly the declared ABI, dispatch rounded-up workgroups, copy to staging, wait for mapping and compare readback.
3. Test partial groups, empty input and invalid host lengths. Propagate validation, device, mapping and comparison errors.
4. Do not substitute CPU execution or a different shader when reporting GPU success.
5. Native readback futures never wake themselves: wgpu runs the `map_async` callback inside a device poll, so `read_typed_buffer_async` completes only while something polls the device. The blocking wrappers (`read_typed_buffer`, `GpuVec::to_vec`, the `_timed` and one-shot functions) therefore call `poll(Wait)` first and then wait for the mapping's own completion, bounded (`completion::blocking`: a park-based wait on the future or `recv_timeout` on the callback's channel, 30 s, then `Error::Map`); one poll followed by one check is a race, because another thread's device poll runs every finished submission's callbacks and can collect this one's after this thread's `poll(Wait)` returned (`tests/concurrency.rs`). Awaiting the future on a native executor that sleeps until woken hangs.
6. The `wasm32` surface (browser, `webgpu` feature enabled only for wasm32) has no blocking and no clocks: `new_async`, buffers, typed `dispatch`/`submit` and `read_typed_buffer_async` exist; the blocking readbacks, the `_timed` and one-shot `dispatch_f32`/`dispatch_u32` functions, the `graph` module and `pool_read` are `cfg(not(target_arch = "wasm32"))`, and `WgpuJob::wait`/`status` return at once there, so synchronise with an awaited readback. Gate new blocking or timed code the same way, and run `cargo xtask check-web` (needs Chrome) after touching it.

7. The shader a kernel runs is its embedded WGSL artifact (`KernelDescriptor::artifacts`), checked by `gust::artifact::verify_artifact` against the descriptor (D17) before a pipeline exists; only a kernel without one, in a build with the `slang-runtime` feature (`dev`), is compiled by Slang at run time, and a strict build without the artifact is `Error::NoArtifact`. wgpu and the driver still compile the WGSL. A missing Vulkan adapter is `Error::NoAdapter`; report any other initialisation failure as what it is (the precompiled consumer prints `GPU initialization failed:` for those), so a test or CI step that expects "no adapter" cannot be satisfied by another error.

Read [headless execution](references/headless-execution.md) for buffer lifecycle and test requirements. `cargo xtask test-exact -p <package> --test <target> <name>` runs one existing standard Rust integration test by exact name with `--include-ignored` and rejects zero, ignored or repeated tests. It certifies test execution, not the test's implementation; inspect the test for real GPU assertions.

Workgroup memory (M7, m7.g1): `Workgroup` arrays and the derived `LocalId`/`GroupId` are not resources, so a descriptor, a bind group and a `dispatch_buffers` slice list never mention them. A buffer that holds one value per workgroup (a block reduce's partials) has a length other than the element count, so bind it with `BufferBinding::read_write(..).independent_length()`; the dispatch otherwise refuses it as `BufferLength`.

Extents, resident vectors and the default device (M7, m7.d and m7.a0; D84, D102): `gust::Extent { x, y, z }` is what `call_extent`, `submit_extent` and `dispatch_extent` take (`call`, `submit` and `dispatch` mean `Extent::linear`). An axis of 0 runs nothing and is `Ok`; each axis is rounded up to whole workgroups, and the rounded product may be at most `Extent::MAX_INVOCATIONS` (2^32), else `Error::DeviceLimit` before any pipeline, uniform or upload exists. A `Shared` binding holds exactly `checked_total()` elements. `GpuVec<T>` stays on a device (`from_slice`, `zeroed`, `to_vec`; the `_on` forms take a `DeviceHandle`); its storage comes from the device's `BufferPool`, so the raw buffer behind it is the whole size class and a hand-written binding must be sized to `len()` bytes (`as_entire_binding()` shows the previous owner's tail; the generated host code still does this, see NEXT_TASKS). Zeroed hand-outs are cleared in a submission of their own. `default_device()` opens `DeviceOptions::default()` (high performance adapter; on native `LimitsPolicy::Adapter`, so the adapter's own buffer and binding limits, and on `wasm32` `LimitsPolicy::Default`), which `set_default_options` can change only before the first open (`Error::DefaultDeviceOpened`); `HeadlessDevice::new()` keeps wgpu's portable defaults, so a kernel that fits one can exceed the other's limits.
