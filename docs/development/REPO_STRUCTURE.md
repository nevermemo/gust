# Repository structure

GUST is organized so source, proofs, generated artifacts, tools, and agent operating state have distinct homes. Keep public entry points small and move implementation details behind crate modules or example modules as they grow.

## Top-level layout

```text
crates/                 the Rust crates (four are publishable, `gust-algo` is not; D110)
examples/               runnable vertical proofs, each with a thin src/main.rs
tests/fixtures/         compiler source/golden fixtures shared by tests
generated-wgpu/         ignored local Slang/WGSL/SPIR-V/host output regenerated by examples
docs/                   human and agent documentation
  development/          compact status, active queue, contracts, handoff and history
scripts/probes/         non-Rust native probe sources used by xtask
xtask/                  cross-platform project automation
.github/                VS Code/Copilot agents, prompts and hooks
.vscode/                workspace tasks only
.ai/                    generated or machine-readable state only, including agent context index
```

## Operational state

Human-readable operating state lives in `docs/development/`:

- `STATUS.md` — current owner, active claim, current contracts, and latest evidence.
- `NEXT_TASKS.md` — active, deferred, and claimable work only.
- `HANDOFF.md` — compact pickup notes for future humans and agents.
- `history/CHANGED_FILES.md` — historical baseline inventory (2026-09-07 takeover hashes; archived).
- `tasks/` — compact task contracts with source/API boundaries and exact checks.
- `history/` — completed-task and superseded-handoff history.

`.ai/` is reserved for machine-readable/generated state such as `VALIDATION.json`,
`BASELINE.sha256`, and `AGENT_CONTEXT.json`. Do not add narrative markdown there.
`VALIDATION.json` is local and untracked because it records one machine's run.

## Crates

Keep the current crate split until a measured need appears:

- `gust`: public API, descriptors, ABI metadata, Rust shadow types, Slang/compiler bridge, reflection and SPIR-V helpers.
- `gust-macros`: proc-macro validation, expansion and Rust AST -> Slang lowering.
- `gust-wgpu`: headless wgpu runtime, buffers, dispatch, pipeline cache, graph and pool support.
- `cargo-gust`: the `cargo gust` subcommand; collects `#[gpu]` kernels, compiles them with the pinned Slang, writes and re-checks the committed `gust-artifacts/` (`init`, `build`, `check`, `doctor`, `slang`). A binary only.
- `gust-algo`: device-resident algorithms (reduce, scan, compact) written as GUST kernels over `GpuVec`; a workspace crate that is not published (`publish = false`, D110).
- `xtask`: dependency-light project automation and validation commands.

Prefer internal modules before new crates. Split a crate only when there is a stable public boundary, independent dependency profile, or clear compile-time/ownership benefit.

## Examples

Every example has a tiny `src/main.rs` that delegates to `src/app.rs`. The app module may contain GPU module definitions, host/reference code, artifact export and tests. For examples above roughly 300 lines, prefer the next split:

```text
src/main.rs       binary entry point only
src/app.rs        top-level wiring and public run/main function
src/gpu.rs        #[gpu] module and descriptors
src/cpu.rs        independent host reference
src/host.rs       runtime setup, buffers, graph/pool helpers, artifact export
src/tests.rs      ignored example validation tests
```

Small examples may stay at `main.rs + app.rs`; large examples should move toward the fuller shape as they change for feature work.

## Generated artifacts

`generated-wgpu/` is a local ignored output directory. Regenerate it with
`cargo xtask export-artifacts`, `cargo xtask check-artifacts`, `cargo xtask
check-full`, or a relevant example binary. Never hand-edit generated artifacts or
commit them upstream; they are reproducible evidence, not source. Golden expectations
that should be reviewed live under `tests/fixtures/`.

## Tooling

Use `cargo xtask ...` for cross-platform workflow commands. No shell or PowerShell scripts are tracked; see D27, which `cargo xtask lint` enforces. Native probe source files (C++, not scripts) belong under `scripts/probes/` until a later dedicated move to `tools/slang-reflect/`.
